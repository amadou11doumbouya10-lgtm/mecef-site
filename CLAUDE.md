# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Next.js dev server
- `npm run build` — production build
- `npm run start` — run the production build
- `npm run lint` — run Next.js/ESLint checks

There is no test suite configured yet.

## Architecture

Next.js 14 App Router site for MECEF ET FILS, a Guinean BTP (construction/public works)
company. Static marketing site with six main pages plus four activity-pole pages, no database,
live at https://mecef-site.vercel.app (see Deployment below). Everything lives under `src/`
(App Router convention with a `src` dir), matching the developer's other project
(`vision-amah`) — see `docs/PROJET.md` for the full technical writeup.

- `src/app/` — one route per page (`/`, `/qui-sommes-nous`, `/realisations`, `/materiel`, `/partenariats`, `/actualites`, `/contact`, `/mentions-legales`, `/confidentialite`), each a `page.tsx`. `src/app/layout.tsx` wraps every page with `TopBar`/`Navbar`/`Footer` and imports `./globals.css`. Every page sets a location-aware `title`/`description` (Siguiri / Haute Guinée / Conakry) for local SEO. The architecture (top contact bar, "Demander un devis" CTA, "Nos pôles" menu, richer pôle pages, Actualités, legal pages) was modelled on the *structure* of centralgroupgn.com (2026-11-07) — none of its copy, branding or claims (e.g. "réponse sous 24 h") were reused.
- `/contact` reads `searchParams.objet` (which makes it a dynamic route): every "Demander un devis" button links to `DEVIS_HREF` (`/contact?objet=devis`, in `src/lib/site.ts`) and the form's subject select is preselected. `/actualites` renders `src/data/actualites.ts` — 8 dated posts from MECEF's Facebook page about the Lot 10 chantier (sources and the one discarded post in `CONTENU_SITE.md` §8). `/mentions-legales` and `/confidentialite` are `noindex` and left out of `sitemap.ts`; their wording still needs MECEF's validation (§9 — the publication director's name is deliberately not stated). Homepage follows the "Mélange A + B" mockup chosen by the developer on 2026-11-07 (Design canvas https://claude.ai/artifact/PKb5Y9yQwZXbVYW6w5wqg4, artboard `AccueilMix`), with a deliberate background rhythm dark → gold → dark → cream → dark → gold: `Hero` (photo carousel, no stat cards; from `md` up a row of 4 pôle tabs 01–04 sits at its bottom, Central Group style, so the progress bars and the Lot 10 caption are raised via `indicateursHaut`) → `Stats` (gold band) → `PartnerStrip` (static row) → `HomeQuiSommesNous` (cream section; Présentation paragraph + repère chips + link on the left, photo + the 3 mission cards of `NotreMission.tsx` on the right, text copied from `CONTENU_SITE.md` §2) → `Sectors` (photo cards) → `HomeRealisations` (Lot 10 "Réalisation phare" mosaic + "Autres références" table) → `HomeCta` (gold band). Apart from the pôle pages (new template, see below), the inner pages have not been restyled to the mockups yet (only the shared TopBar/Navbar/Footer/button changes reach them).
- `HeroBackground.tsx` overlays (shared by the homepage hero and the `/materiel` banner) were lightened on 2026-11-07 because the real photos were barely visible: mobile gets a uniform `charcoal/45` veil (text spans the full width), desktop (`lg`) a left→right gradient behind the left-aligned text with the right half of the photo left clear, plus top (navbar) and bottom (section join) fades. Don't reintroduce a full-surface dark veil or radial vignette.
- `src/app/contact/actions.ts` — a `"use server"` Server Action (`sendContactMessage`), validated with `zod`, invoked directly as the `<form action={...}>` handler in `src/components/Contact.tsx` via `useFormState`/`useFormStatus`. Sends through Resend (`RESEND_API_KEY` in `.env.local`); currently blank, so it fails gracefully with a French message instead of calling Resend.
- `src/data/realisations.ts` — typed data module (`Realisation` interface + `realisations` array), the single source of truth for chantier references. Consumed by `src/components/Realisations.tsx` (filterable grid on `/realisations`) and `src/components/HomeRealisations.tsx` (homepage). Optional fields drive the homepage: `enAvant` (the one "Réalisation phare" — currently Lot 10), `couverture` (its large mosaic photo) and `chiffres` (its key facts); "Autres références" is computed, not curated — the 4 largest `montant`s excluding the phare, shown newest first.
- `src/components/` — one component per page section (`Navbar`, `Hero`, `Stats`, `PartnerStrip`, `HomeQuiSommesNous`, `Sectors`, `HomeRealisations`, `HomeCta`, `Realisations`, `RealisationGallery`, `NotreMission`, `Partenariats`, `Contact`, `Footer`), plus `TopBar.tsx` (thin contact strip above the Navbar; it scrolls away, only the Navbar is sticky, so the hero's `-mt-20` is unaffected) and shared helpers: `Reveal.tsx` (scroll-triggered reveal, see Motion below), `RegionMap.tsx`/`LeafletMapInner.tsx` (real Leaflet map, see below), `Direction.tsx` (Direction section with an optional-prop portrait placeholder), and `PoleActiviteDetail.tsx` (shared template for the four `/activites/*` pages). Referenced by absolute imports (`@/components/...`, `@/data/...`, `@/lib/...`) via the `@/*` path alias (maps to `./src/*` in `tsconfig.json`).
- `src/components/Realisations.tsx` is a client component: the `/realisations` grid with category filter chips backed by `useState` (its former homepage `variant="featured"` was replaced by `HomeRealisations.tsx`, a server component). It also exports `RealisationCard`, reused by `PoleActiviteDetail.tsx`.
- `src/components/Navbar.tsx` — "MECEF ET FILS" wordmark; desktop entries Qui sommes-nous · **Nos pôles** (dropdown built from `activites.ts`, opens on hover or click, closes on Escape / outside click / route change) · Réalisations · Matériel · Partenariats · Actualités, plus the gold "Demander un devis" button. "Accueil" is carried by the logo and "Contact" by the button on desktop; both stay in the mobile menu, which also lists the 4 pôles. Desktop layout only from `xl` up, with the bar widened to `max-w-7xl` — 6 entries + button don't fit narrower; below `xl` it's the burger menu. Active link gold with a 2px underline. Transparent at the top of the page, switches to `bg-charcoal/95` + border once scrolled past 8px or when the mobile menu is open. Sections with a full-bleed photo at the top of the page (the homepage `Hero`, the `/materiel` banner, and `PageHero.tsx`) carry `-mt-20` so the photo slides under the bar — **this is coupled to the Navbar's `h-20`; update every `-mt-20` if the bar height changes.** The legal pages are the only ones starting on plain charcoal.
- `src/components/PageHero.tsx` — photo banner (breadcrumb, gold label, large serif title, optional subtitle/intro/actions, same left-weighted scrims as `HeroBackground`) at the top of every inner page: the 4 pôle pages (their `image`), `/realisations`, `/qui-sommes-nous`, `/partenariats`, `/actualites`, `/contact` (`/materiel` keeps its own carousel banner). Layout modelled on centralgroupgn.com's pillar pages, as are the pôle pages' centered section titles and alternating charcoal / charcoal-card backgrounds.
- `src/components/PartnerStrip.tsx` — static row of partners (it used to be an infinite marquee, but with only 5 partners the duplicated list showed twice side by side on desktop and read as a bug — don't bring the marquee back unless the list grows a lot). Only partners with a verified official logo (AGEROUTE, UCEP — `public/logo/partenaires/`) get an image; the rest stay as text rather than inventing a visual.
- `src/data/stats.ts` — key figures, shown only in the gold `Stats.tsx` band (with its scroll-triggered counter). The hero's floating stat cards were removed on purpose: showing the same figures twice was flagged as redundant.
- `src/components/Footer.tsx` — 4 columns (brand + devis button, navigation, Nos pôles, contact); bottom bar carries the copyright, RCCM/NIF, links to the two legal pages, and a developer credit "Site réalisé par Vision Amah" linking to https://vision-amah.vercel.app (the developer's own site), requested by the developer.
- `src/components/Sectors.tsx` — the 4 activity-pole photo cards (numbered 01–04), each a `<Link>` to `/activites/[slug]`, sourced from `src/data/activites.ts` including its `image` (not hardcoded — keeps homepage cards and detail pages in sync).
- `src/app/activites/{slug}/page.tsx` (4 routes) + `src/data/activites.ts` — one page per pôle d'activité. **The 4 pôles do not map 1:1 onto `realisations.ts`'s `categorie` field** (e.g. "Digues et routes" / Mandiana is categorized `Travaux routiers` but belongs to the `Aménagement` pôle) — each pôle instead lists its réalisations by exact `{ titre, lieu }` match. `prestations` splits the client-provided keywords (their "Description de l'entreprise" doc) into one card each — never add descriptions beyond what's in `activites.ts`. `zone` ("en Haute Guinée" / "en Haute Guinée et à Conakry", with its preposition) is derived from the pôle's réalisation locations and feeds the SEO title and the "Zone d'intervention" section. `PoleActiviteDetail.tsx` template: breadcrumb → header (icon, "Pôle d'activité 0X", zone, devis + phone buttons, photo) → "Ce que nous prenons en charge" → Références liées → Zone d'intervention (location chips from its réalisations) → `HomeCta` gold band → other pôles. A "méthode" and an FAQ section are planned but wait for client content (`CONTENU_SITE.md` §7) — don't fill them with invented text.
- `src/components/RegionMap.tsx` / `LeafletMapInner.tsx` — real interactive Leaflet map (Siguiri + Conakry markers), replacing an earlier abstract SVG diagram. `LeafletMapInner.tsx` is loaded via `next/dynamic(..., { ssr: false })` from `RegionMap.tsx` (a `"use client"` wrapper — Next only allows `ssr: false` dynamic imports from Client Components, and Leaflet touches `window` at import time). Tiles come from the bare `tile.openstreetmap.org` domain (no `{s}` subdomain rotation — `a/b/c.tile.openstreetmap.org` were unreachable in the sandbox network used to build this; the bare domain works and is fine for a low-tile-count 2-marker map) — free, no API key. **Do not switch to CARTO's `dark_all` basemap tiles** (`basemaps.cartocdn.com`) — despite their reputation as a free dark-tile source, they now render an "API KEY REQUIRED" watermark without a registered account. The dark look instead comes from a CSS filter (`invert(1) hue-rotate(180deg) ...`) scoped to `.leaflet-tile-pane` in `globals.css`, leaving markers/popups/controls unaffected. Markers use `L.divIcon` (never `L.Icon.Default`, whose icon paths break under bundlers).
- `src/lib/site.ts` — `SITE_URL` (from `NEXT_PUBLIC_SITE_URL`), `DEVIS_HREF`, `TELEPHONES_AFFICHES` (display strings, same order as `ORG.telephone` used for `tel:` links) and org contact info, shared by `metadataBase` in `layout.tsx`, `sitemap.ts`, `robots.ts`, and the JSON-LD `GeneralContractor` schema injected in `layout.tsx`.
- `docs/CONTENU_SITE.md` — source-of-truth text content (copy, numbers, chantier references) for every page. Never invent content; add it here first, then reflect it in `src/data/realisations.ts` or the relevant component.
- `public/logo/mecef-mark.png` — the real client logo, pictogram only (transparent background, white-stroked shapes so it reads fine directly on the charcoal theme — no chip/backing needed). `public/logo/mecef-logo.png` is the fuller lockup (pictogram + "MECEF" wordmark). Both were cropped from the client-provided `mecef_logo_hd.png` (not in the repo — lives in the client's Downloads). `src/app/icon.png`, `apple-icon.png`, and `opengraph-image.png` were generated from the same source and are auto-wired by Next's App Router file conventions — no code references them explicitly.
- `src/components/Hero.tsx` / `HeroBackground.tsx` — full-bleed background hero (`min-h-screen`, text overlaid with a charcoal gradient scrim for legibility), mirroring the pattern in the developer's other project's `Hero.tsx` + `VideoBackground.tsx` (a sibling project at `Desktop/it-solutions`, same author as `vision-amah`) but with a crossfading image carousel instead of a background video, and MECEF's charcoal tones instead of black. `HeroBackground` takes an `images` array; empty by default, in which case it renders a geometric SVG placeholder (`HeroPlaceholder`) instead of a stock photo. Progress-bar indicators only render when `images.length > 1`.
- **Motion** (2026-11-08, CSS only, no animation library): hero photos crossfade every 6 s with a slow Ken Burns zoom (outer div = 1 s opacity, inner image = 7 s `scale-[1.08]`, started after mount so the first photo doesn't load pre-zoomed); one progress bar per photo fills over the interval (`@keyframes hero-progress` in `globals.css`, duration passed inline); hero text enters in cascade (`animate-fade-up` keyframes in `tailwind.config.ts` + `[animation-delay:…]`); pôle cards, reference rows and actualités stagger in via `Reveal` `delay`; the Lot 10 mosaic uses `Reveal variant="wipe"` (bottom-up clip-path). `Reveal` also takes `as="li"` to animate list rows with valid HTML. Everything is disabled under `prefers-reduced-motion` (`motion-reduce:` variants + the JS checks). **Gotcha:** never put the `clip-path` on the element the IntersectionObserver watches — Chrome treats a fully clipped target as never intersecting, so it never reveals (this happened: the mosaic stayed empty); `Reveal` puts it on an inner wrapper. When verifying reveals with headless Chrome, wait for hydration before scrolling, or blocks above the fold at hydration time stay hidden in the capture (a test artefact, not a bug).
- `public/images/` — **real MECEF chantier photos** (client-provided via WhatsApp, 2026-11-07), replacing the earlier stock photos: `hero-1…5.jpg` (homepage carousel), `materiel-1…5.jpg` (`/materiel` banner carousel), `activite-{construction,amenagement,equipements,prestations}.jpg` (one per `/activites/*` page, `image` field in `activites.ts`), and `mission.jpg` (`NotreMission.tsx`). Sources are low-res phone photos (≤960 px wide, almost all portrait), so they were processed with Pillow: EXIF orientation applied and metadata stripped, mild autocontrast/saturation, Lanczos upscale (1600 px wide for the carousels, 1344×756 16:9 crops for the pôle pages, 1200×900 4:3 for mission) plus unsharp mask. Carousel images are kept **uncropped portrait** — each entry carries an optional `position` (CSS `object-position`) choosing which horizontal band shows on desktop, so mobile still sees the full photo; the `/materiel` banner is ~3:1 on desktop, so its band choice matters most. The client's batch also contained Facebook screenshots (UI chrome, duplicates of the real photos) — never use those; their captions (dates, 1 164 m béton armé, dalots) describe the voirie du fleuve Niger in Siguiri (2023), which the developer confirmed (2026-11-07) **is the `Lot 10 — AGEROUTE` réalisation** — so Lot 10 now has `lieu: "Siguiri"`, `annee: 2023` and a `photos` gallery (`public/images/realisations/lot-10-01…12.jpg`, 900×1200 3:4 tiles, ordered by chantier phase). Source details are recorded under Lot 10 in `docs/CONTENU_SITE.md`; the montant is still unknown.
- `src/components/RealisationGallery.tsx` — photo grid for any réalisation with a `photos` array, rendered at the bottom of `/realisations` with an anchor id from `realisationSlug()` (`src/data/realisations.ts`); `RealisationCard` shows a "Voir le chantier en images →" link to that anchor whenever `photos` is set (`/realisations` and pôle pages), and the homepage's "Réalisation phare" block links there too. Adding photos to another réalisation needs no component change. **`activites.ts` matches réalisations by exact `{ titre, lieu }`** — when a réalisation gains a `lieu` (as Lot 10 did), update its reference in `activites.ts` too, or it silently disappears from its pôle page. Earlier stock batches once carried an Alamy watermark (2026-08-31) — if stock is ever reintroduced, boost contrast and look for watermark text before wiring it in.

## Conventions

- Import via the `@/*` alias (maps to `./src/*`), not relative paths across top-level folders.
- Never hardcode brand colors as hex in components — use the Tailwind tokens defined in `tailwind.config.ts` (see palette below).
- `.env.local` holds `RESEND_API_KEY` (currently blank) for the contact form's email integration.
- Key server-side logic (`src/app/contact/actions.ts`) carries brief French comments explaining non-obvious constraints (e.g. why a missing API key fails without calling Resend). Follow that pattern for new server-side code in this repo; it's a deliberate project convention, not the general default.

## Visual identity

Deliberately distinct from the developer's other project (`vision-amah`): serif + mono
typefaces instead of Geist, charcoal palette with the logo's own accents (gold/sky/leaf) instead of
Vision Amah's palette. Sober, editorial tone — no gradients, no heavy drop shadows, no generic stock
icons or photos.

**Palette** (`tailwind.config.ts`). The single `laterite` accent (`#D9622B`) from the original
brief was replaced (2026-10-14) by the three accent colors of the client logo; `gold` is the
main accent (buttons, links, active states, markers, and the two full-width gold bands of the
homepage), `sky`/`leaf` are secondary touches (e.g. `sky` for location pins).

**Contrast rules** (WCAG AA, checked 2026-11-07): text on `gold` is always `charcoal` — `.btn-primary`
was cream-on-gold (≈ 1.5:1, unreadable) and is now charcoal-on-gold (≈ 9:1). Small labels use
`warmgray`/`warmgray-light`, not `warmgray-dark` (≈ 3.3:1 on charcoal) — except on cream, where
`warmgray-dark` passes (≈ 4.6:1). Cream sections use `charcoal` / `charcoal-muted` text and
`cream-border` rules; `.btn-dark` / `.btn-outline-dark` (in `globals.css`) are the button variants for
cream and gold backgrounds.

`next/font/google` in `src/app/layout.tsx`.

## Deployment

Hosted on Vercel, project `vision-amah/mecef-site`, production URL https://mecef-site.vercel.app.

- The GitHub repo is **not** connected to Vercel's Git integration — `git push` does not deploy. Deploy manually with the Vercel CLI (`vercel --prod`), after a passing `npm run build`.
- On Windows, stop the dev server before a local `npm run build` — both write to `.next/` and the build fails with `EPERM` otherwise.
- Vercel Production env: `NEXT_PUBLIC_SITE_URL=https://mecef-site.vercel.app` (without it, `src/lib/site.ts` falls back to `https://mecefetfils.com`, a domain MECEF doesn't own yet). `RESEND_API_KEY` is not set on Vercel either, so the contact form shows its graceful error in production too.

## Stack decisions

This is a showcase/vitrine site, not a data-driven app — the stack is intentionally kept light:

- **No database, no Prisma.** Content lives in `src/data/*.ts` (typed data modules) or hardcoded in section components. The only exception that would justify adding a DB later is if MECEF wants a CMS to edit `réalisations` without touching code, or wants to persist contact-form submissions.
- **Resend over Nodemailer** for the contact form (`src/app/contact/actions.ts`) — no SMTP setup, plain API call, works cleanly from a Server Action. Note: the `from` address needs a verified sending domain in Resend before production use.
- **Fonts via `next/font/google`** (Fraunces, IBM Plex Mono) — no separate npm package needed; Next self-hosts the font files, which is better for performance and avoids external requests to Google Fonts.
- **`lucide-react`** for icons — lightweight, tree-shakeable, simple line icons (never stock-style icon sets).
- **`zod`** validates the contact form server-side inside `sendContactMessage` — prevents empty/malformed submissions from reaching Resend. Installed as `zod@4`, which changed error-customization syntax (`error:` instead of `errorMap:`) versus zod 3 — keep that in mind when reading examples online.
- **`react-leaflet` v4 + `leaflet`** for the `/qui-sommes-nous` map — pinned to v4 for React 18 compatibility (v3 targets React 17). No API key needed (see `RegionMap.tsx` notes above); OpenStreetMap tile usage policy just asks for reasonable traffic and a valid attribution, both satisfied here.
